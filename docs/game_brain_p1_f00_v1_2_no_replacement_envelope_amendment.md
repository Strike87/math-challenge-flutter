## 2. Superseding rule: no-replacement confirmatory envelope

Phase-1 P1-F01 confirmatory eligibility remains exactly:

- Standard mode;
- 1 player;
- Choice4 answer style;
- Adaptive OFF;
- manual Easy / Medium / Hard (player-configured difficulty route).

**Replacement-generated questions are outside the confirmatory evidence
envelope.** A switchOp replacement canonical gameplay opening remains full
canonical gameplay truth and is not erased, denied, or reclassified as
nonexistent; it is prospectively excluded from the v1.2 confirmatory-eligible
`O_raw` population only.

If switchOp/replacement is requested during an otherwise eligible integrity
window:

1. a synchronous local P1-F01 admission-disabled / non-confirmatory state
   must be established **before** the replacement `_generateQ()` executes;
2. no further P1-F01 admissions from that run may enter confirmatory
   evidence;
3. gameplay continues normally and unchanged;
4. the power-up is not blocked, delayed, consumed differently, or capped.

Fail-closed ordering clarification:

- The synchronous local exclusion state is the eligibility firewall. It must
  exist before the replacement-generated canonical question opening.
- Durable `LEFT_UNCLEAN` bookkeeping may complete asynchronously after that
  point; it is bookkeeping evidence of the exclusion, not a prerequisite for
  gameplay progression.
- Gameplay must never await that persistence.

This is a measurement/protocol rule only:

```text
mayAffectGameplay = false
```

The fail-closed transition is an integrity-bookkeeping state change owned by
the measurement layer (`_p1F01IntegrityMeasurementFailed` → window left
unclean instead of clean closure). It must never decide whether gameplay
opens, proceeds, closes, generates a question, or records a canonical
terminal.

## 3. Frozen bound evidence (uniform conservative K_under ceiling)

| Fact | Basis |
| --- | --- |
| A no-replacement supported run has at most 25 eligible canonical openings | `maxTurns = 1 × questionTarget`; UI options `{10, 15, 20, 25}` |
| Warm-up questions are inside that same budget | Warm-up questions are generated by the same turn flow and consume turns through the unconditional terminal turn increment |
| Answer / incorrect / timeout / skip all consume the normal turn budget | All three terminal routes converge on one handler performing exactly one turn increment per consumed turn |
| switchOp is the only supported-envelope generation path that bypasses the turn budget | Exhaustive generation-path trace; replacement claims a terminal without incrementing turns |
| Therefore the prospective uniform conservative `K_under` ceiling is **25** | Sum of the above |

This ceiling is uniform across all admissible confirmatory executions and is
stated conservatively (per-window undercount cannot exceed the openings of
one window). It satisfies the v1.1 §12 requirement that `K_under` be finite,
uniform, and validatable before confirmatory collection opens.

## 4. Accounting conclusions carried forward

- Production `K_over` remains **0**: the production admission path is invoked
  synchronously from the canonical opening site, while durable accounting
  increments are produced through that admission's atomic SQLite transaction;
  no durable unit can exist without a canonical opening that has just
  occurred. Validation-only debug probe surfaces are debug-build + flag gated
  and excluded from production accounting.
- Divergence direction remains **UNDERCOUNT_ONLY**.
- Canonical `O_raw` truth continues to originate at the canonical eligible
  chooseDifficulty opening. Durable storage records that truth; the storage
  commit does **not** redefine whether the canonical opportunity occurred.
- `LEFT_UNCLEAN` windows retain their canonical openings as historical truth.
  Non-clean status excludes a window from confirmatory use; it does not
  declare its openings nonexistent.
